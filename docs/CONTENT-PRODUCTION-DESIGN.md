# 团建中控｜GPT 内容制作自动化系统设计说明书

**版本：V1.0**
**适用项目：teambuilding-workflow-dashboard**
**目标：将现有的团建图文生产流程完整纳入"团建中控"，支持从人工控制逐步升级到单账号、多账号、多对话的持续自动生产。**

## 一、项目目标

当前团建图文作品的标准生产流程是：

1. 选择一个已经训练好、已经锁定模板规则的 GPT 对话；
2. 上传一个小红书素材帖子，包括图片和 TXT 文案；
3. 同时发送素材迁移提示词；
4. 等待 GPT 返回逐页出图计划；
5. 发送一次确认指令 1；
6. 等待 GPT 生成封面和全部内页；
7. 再发送小红书文案生成提示词；
8. 等待文案完成；
9. 下载图片、保存文案；
10. 将图片和文案打包到本地成品文件夹；
11. 校验成品完整性；
12. 更新素材使用次数并归档素材；
13. 继续处理下一条素材。

软件最终要把以上流程拆成独立、可复用的小模块，再由不同模块组合出：

- 人工控制；
- 选材后自动；
- 单账号全自动；
- 定时全自动；
- 多账号全自动；
- 单账号多对话全自动。

重点不是继续写多个互相独立的自动化脚本，而是建立一套统一的：

**任务队列 + 状态机 + 页面检测器 + 工作流模块 + 检查点恢复系统。**

所有模式都共用这一套底层能力。

## 二、当前项目基础

根据当前仓库的最新开发记录，项目已经具备以下基础：

- 已有 GPT 网页执行层，可以识别当前对话所处的计划、等待确认、图片、文案、脚本降级和真实限额状态；
- 已经统一了素材上传、文案保存、图片下载、工作包打包和使用次数归档；
- 单账号、单帖子、当前模板会话的真实闭环已经跑通；
- 一次真实任务已经完成：上传12张素材图和1份TXT；等待计划；只发送一次 1；生成10张1086×1448图片；取得完整文案；打包成品；将素材移动到"已使用一次"；

当前尚未完全通过的关键门禁是：

- 父合集拆成多个帖子后严格串行；
- 重启、断网后的检查点恢复；
- 触顶后自动探测和继续；
- 多账号真实运行；
- 超过10页后的续批生产。

目前仓库正式收口的生产模式只有：

- 手动模式；
- 单账号单模板·永不停歇；
- 多账号单模板·永不停歇。

同时，当前会话模式不会重复注入母版提示词；只有明确选择模板初始化时，才重新加载母版迁移规则。网页执行层也已经开始使用结构化的当前会话状态快照。

因此，本次设计不应推翻现有生产链，而应该在现有状态机和单账号闭环基础上继续扩展。

## 三、核心设计原则

### 1. 模式只是预设，不是独立代码分支

不要为"手动、半自动、全自动、定时、多账号、多对话"分别写六套流程。

正确方式是：
1. 先把生产动作拆成模块；
2. 再建立统一的工作流执行器；
3. 每种模式只是选择了不同的触发器、模块和参数。

### 2. 暂停不是一种模式

"暂停"是全局控制动作，不应作为模式存在。

统一控制按钮：
- 开始；
- 暂停；
- 继续；
- 安全停止；
- 强制停止；
- 跳过当前任务；
- 转人工处理。

### 3. 一个帖子必须完整结束后才能处理下一个帖子

无论选择的是单个帖子、多个帖子，还是一个父级合集文件夹，都必须拆成独立帖子任务。

严格顺序：帖子A完整结束 → 校验 → 打包 → 归档 → 才能开始帖子B

### 4. 只有成品校验成功才能增加素材使用次数

素材被上传，不等于素材已成功使用。只有以下条件全部通过，才允许增加使用次数、移动素材文件夹。

成功条件：
- 成品图片存在且可解码；
- 图片数量满足本批计划；
- 文案 TXT 存在且非空；
- 生产记录存在；
- 成品文件夹真实存在；
- 成品图不是简单复制的源素材；
- 打包状态为完成。

## 四、内容制作界面布局

整体采用左右双栏结构。

### 1. 左侧素材区
- 读取素材库、显示素材分类、选择帖子
- 构建本轮任务队列、显示素材使用次数
- 绑定模板或 GPT 对话、设置生产模式

### 2. 模板或对话绑定区
- A. 复用当前已训练对话（不重复发送母版）
- B. 新建全新对话（初始化模板后绑定）

### 3. 右侧 GPT 网页区
- 切换账号窗口、切换历史对话、打开模板会话
- 自动任务运行时仅切换查看，不改变任务绑定

### 4. 页面状态浮层
显示当前任务、帖子、模板、账号、阶段、等待时间、计划页数、预期图片数、检测图片数、下次自动动作、限额恢复时间、检测证据。

## 五、统一生产状态机

### 主状态
IDLE → MATERIAL_SELECTED → SESSION_PREPARING → UPLOADING → ATTACHMENTS_READY → PROMPT_READY → SENDING → WAITING_PLAN → PLAN_READY → CONFIRMING → WAITING_IMAGES → IMAGES_READY → REQUESTING_COPY → WAITING_COPY → COPY_READY → SAVING_COPY → DOWNLOADING → PACKAGING → VALIDATING → ARCHIVING → COMPLETED

### 异常状态
NETWORK_RETRY, PAGE_RECOVERY, QUOTA_PAUSED, LOW_OUTPUT, DEGRADED_OUTPUT, HUMAN_REQUIRED, FAILED, SKIPPED

## 六、页面检测机制

多信号综合判断：
1. 发送按钮检测
2. 消息流检测（内容稳定+停止生成+无新增节点）
3. 附件上传检测
4. 出图计划检测（P1..Pn, 总页数, 本批页数, 首批10页）
5. 确认指令检测（只发一次，防重复）
6. 图片生成检测（折叠文件组、下载链接、图片尺寸）
7. 文案检测（最低有效字符300，推荐600+）
8. 错误与降级检测（网络错误、重试按钮、限额、验证码、脚本/Python、低图数）

## 七、基础工作流模块

A. 触发模块（手动/定时/启动后/登录后/网络恢复/唤醒后/限额恢复/任务完成）
B. 素材模块（单选/多选/递归拆分/按使用次数/按标签/排除已占用）
C. 会话模块（当前对话/模板对话/新建/初始化/切换账号/绑定任务）
D. 页面交互模块（上传/填写/发送/确认/请求文案/复制/下载）
E. 检测模块（附件完成/发送按钮/回复停止/计划完成/图片完成/文案完成/网络错误/限额/低图数/降级/验证码）
F. 控制模块（等待/定时/条件/循环/重试/跳过/暂停/转人工/停止）
G. 输出模块（保存TXT/下载图片/创建成品/重命名/写记录/校验/查重/打包/更新使用次数/移动素材/日志）

## 八、生产模式定义

1. **人工控制** — 用户全权操作，上传按钮不自动发送
2. **选材后自动** — 用户选材，软件自动从上传到归档
3. **单账号全自动** — 自动选材+持续生产+限额暂停+到点探测
4. **定时单账号全自动** — 单账号+定时触发+工作时间+恢复
5. **多账号全自动** — 独立账号worker+独立额度+素材占用锁+调度
6. **单账号多对话巡检** — 高级实验模式，最后开发

## 九、低图数、限额和重试策略

- 不硬编码官方额度，记录实际页面信号和真实时间
- 关键时间字段：confirm_sent_at, image_generation_detected_at, first_image_ready_at, last_image_ready_at, quota_detected_at, next_probe_at
- 低图数判定：计划>3 + GPT停止 + 回复稳定 + 实际1~3张 + 无继续生成迹象
- 网络错误退避：2分钟→5分钟→10分钟，最多三次
- 额度恢复后重试发送修复提示词

## 十、工作流组合器

模块化工作流编辑器，每个模块可设置：启用/顺序/超时/重试/失败动作/输入来源/输出字段/人工确认/检查点

系统提供官方预设，用户可复制修改保存为自定义工作流。

## 十一、任务检查点与断点恢复

每完成一个关键动作立即写检查点。重启/断网/浏览器恢复后读取检查点→检查真实页面→对比本地记录→确定状态→从安全动作继续。

## 十二、成品打包标准

作品名称/ → P1.png, P2.png, ... → 小红书文案.txt → 出图计划.json → GPT作品记录.json

打包顺序：文案 → 保存TXT → 下载图片 → 统一命名 → 写记录 → 校验

## 十三、素材使用次数系统

SQLite素材表，任务成功后递增使用次数，自动模式按 usage_count ASC → last_used_at ASC → folder_name 选择下一条。

## 十四、开发顺序

1. 阶段一：稳定人工控制
2. 阶段二：选材后自动（优先完成父合集拆帖串行和断点恢复）
3. 阶段三：单账号全自动
4. 阶段四：定时全自动
5. 阶段五：多账号全自动
6. 阶段六：单账号多对话巡检（实验功能）

## 十五、回归测试清单

涵盖：人工控制、选材后自动、状态检测、检查点恢复、限额处理、多账号、单账号多对话、成品与归档。

## 十六、建议新增的仓库文档

- CONTENT-PRODUCTION-DESIGN.md（本文档）
- CONTENT-PRODUCTION-STATE-MACHINE.md
- CONTENT-PRODUCTION-ACCEPTANCE.md
- GPT-PAGE-DETECTION.md

## 十七、最终使用体验

用户只需要：维护素材库、维护模板对话、检查成品、处理异常、发布内容。
系统负责：找素材→传素材→等计划→发1→等图片→出文案→下载→打包→校验→更新使用次数→继续下一帖。
