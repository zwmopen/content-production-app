# 0.16.21 在线设备库存变化自动复查

## 问题

K60 上线时库存充足后，持续在线期间库存降到 8，而自动分发阈值为 10，工作台没有立即补充。发送能力本身正常；K60 后来发生重连后自动发送 `作品集_059[转]` 成功。

## 根因

旧实现使用在线会话级 `Set` 去重，并在库存比较之前就记录设备。只要设备没有离线，后续扫描无论库存如何变化都会直接返回。

## 修复

- 会话记录升级为库存判断指纹 `Map`。
- 指纹包含实时库存、阈值、分类、单次发送数和是否存在候选作品集。
- 指纹变化后重新判断；相同指纹保持幂等，避免任务运行中重复发送。
- 设置阈值变化会立即进入新的判断状态，无需重启。
- 新增 `evaluated` 结构化日志，明确库存来源和更新时间、比较结果、候选、发送动作及跳过原因。

## 现场证据

- 旧版 K60：库存 8、阈值 10，重连后触发批次 `batch-1786336441341-dsirmm`。
- 自动任务：`distribution-1786336441786-001161`。
- 作品集：`作品集_059[转]`。
- 结果：第一次尝试完成，进度 100%；后续在线扫描显示 K60 作品数 15。

该现场证明底层发送和设备名映射正常。本版针对“必须重连才重新判断”的调度根因。

## 验收边界

- 自动测试覆盖持续在线库存变化和阈值变化。
- 真实无需重连的下一次库存下降，需要等手机再次出现低于阈值的自然现场补最终证据；不得伪造手机库存。
