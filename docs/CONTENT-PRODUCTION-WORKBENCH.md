# 团建中控｜内容制作工作台界面设计

状态：当前有效设计
更新：2026-08-07

## 目标

内容制作页不是复杂的素材后台，而是一个围绕真实 GPT 生产流程设计的生产工作台。

核心动线：

```text
选素材 → 选模板/会话 → 上传并生产 → 查看结果 → 打包成品
```

界面必须减少顶部和底部的重复筛选，不让用户在大量条件中来回找入口。

## 一、整体布局

当前主布局保持：

```text
左侧：素材、模板、队列与控制
右侧：真实 GPT 网页
```

右侧 GPT 网页可切换账号窗口、模板会话或历史会话；切换查看不得改变已经运行任务的真实绑定。

左侧内部再分为三个区域：

1. 素材读取与选择区；
2. 模板/会话选择区；
3. 当前任务与生产控制区。

未来若启用本地成品预览，可在最右侧增加可收起的成品抽屉，但不能挤压 GPT 主操作区。

---

## 二、素材读取与选择区

### 2.1 素材库入口

只需要一个素材库根目录。

支持：

- 选择路径；
- 粘贴路径；
- 刷新扫描；
- 递归读取。

### 2.2 文件夹选择规则

一个“帖子文件夹”是最小生产单位。

用户可以：

- 选择一个具体帖子；
- 多选多个帖子；
- 选择一个父合集；
- 多选多个父合集。

父文件夹只作为批量选择入口，系统必须递归拆成独立帖子任务，禁止将多个帖子作为一批附件同时上传到同一会话。

### 2.3 素材卡片字段

每个帖子显示：

- 文件夹名称；
- 图片数量；
- TXT 是否存在；
- 使用次数；
- 内容标签；
- 当前路径；
- 是否已经进入队列；
- 是否被其他任务占用；
- 最近一次生产结果。

使用次数必须同时参考元数据账本和当前数字目录，避免仅依赖物理位置。

### 2.4 轻量筛选

不做大而全筛选后台。第一版只保留：

- 搜索；
- 全部；
- 团建转化；
- 团建游戏；
- 合集攻略；
- 使用次数 0/1/2/3+。

标签是为了快速缩小素材范围，不应成为操作主线。

---

## 三、模板与会话区

### 3.1 模板先分类型，再选具体模板

当前模板至少有两大类型：

#### 游戏模板

- 图上文字较多；
- 适合团建游戏、小游戏、破冰、玩法说明；
- 页面重点是游戏名、人数、道具、规则和玩法。

#### 转化模板

- 图上文字较少；
- 适合地点、路线、项目、两天一夜和公司团建；
- 页面重点是视觉、场景、标题和搜索转化。

模板选择采用两级结构：

```text
模板类型 → 具体模板
```

### 3.2 必须有缩略图预览

模板名称不足以区分模板。

每个模板卡片至少显示：

- 模板名；
- 类型；
- 预览缩略图；
- 图上文字量：多/中/少；
- 适用素材；
- 对应 GPT 会话；
- 默认生产提示词；
- 最近成功生产记录。

### 3.3 两种模板使用方式

#### A. 延续现有已调教会话

会话已经完成模板学习和规则锁定时，只上传新素材并发送迁移提示词，不重新上传模板，也不重复注入母版迁移器。

#### B. 创建新模板会话

需要执行：

```text
新建 GPT 会话
→ 上传模板
→ 发送母版迁移规则
→ 等待模板学习完成
→ 保存会话 URL 与模板绑定
→ 后续持续复用
```

模板和 GPT 会话是长期资产，不应每个帖子重新初始化。

## 四、生产区的真实交互模型

人工真实工作流：

```text
上传素材 + 提示词
→ GPT 返回逐页出图计划
→ 用户/系统发送一次“1”
→ GPT 生成图片
→ 系统确认图片完成
→ 发送小红书文案提示词
→ 保存文案 TXT
→ 下载图片
→ 打包到成品库
```

手动和自动必须共用同一工作包、下载、校验和归档后端，只区别“谁触发下一步”。

### 4.1 任务状态可见

每个任务显示：

- 当前素材；
- 当前模板；
- 当前账号/会话；
- 当前阶段；
- 已等待时间；
- 计划页数；
- 本批预期图数；
- 当前实际图数；
- 最近错误；
- 下一动作。

### 4.2 主要控制

统一使用：

- 开始；
- 暂停；
- 继续；
- 安全停止；
- 强制停止；
- 跳过当前任务；
- 转人工。

“暂停”不是一种生产模式。

---

## 五、生产模式只作为工作流预设

当前正式模式：

1. 人工控制；
2. 选材后自动；
3. 单账号全自动；
4. 定时单账号全自动；
5. 多账号全自动；
6. 单账号多对话巡检（实验）。

这些模式不得各写一套互不兼容的业务逻辑。

底层应该拆成可复用模块：

```text
选素材
上传附件
填写提示词
点击发送
检测计划
发送确认
检测图片
请求文案
保存 TXT
下载图片
打包
校验
归档
```

模式只是对模块、触发方式、循环条件和定时条件的预设组合。

## 六、成品区与打包

成品逻辑必须围绕“一个帖子一个成品文件夹”。

推荐结构：

```text
成品库/
└── 作品名/
    ├── P1.png
    ├── P2.png
    ├── ...
    ├── 小红书文案.txt
    ├── 出图计划.json
    └── GPT作品记录.json
```

成品操作：

- 打开文件夹；
- 预览图片；
- 查看文案；
- 重新生成；
- 删除；
- 打包到抖音/小红书待发；
- 标记进入下一分发阶段。

正式打包前必须先取得并校验本轮文案 TXT，再下载和整理最终图片，防止产生缺文案半成品。

---

## 七、产品设计原则

1. 生产页是工作台，不是数据后台；
2. 素材选择、模板选择、生产执行要一眼看懂；
3. 真实 GPT 网页是生产现场，软件状态必须能映射网页真实状态；
4. 一个帖子完整结束后才能开始下一帖；
5. 失败不伪造完成；
6. 手动、自动、AI 调用必须复用同一套底层能力；
7. 模板、会话、提示词和成功作品都应沉淀成长期资产；
8. UI 越少要求用户判断越好，但所有自动动作必须可观察、可暂停、可恢复。

## 八、第一阶段验收

- [ ] 左侧能选择单帖、多帖和父合集；
- [ ] 父合集正确拆成独立任务；
- [ ] 素材卡片显示使用次数和 TXT/图片状态；
- [ ] 模板先选类型再选具体模板；
- [ ] 每个模板有缩略图预览；
- [ ] 已调教会话不会重复注入模板；
- [ ] 新模板可通过初始化流程建立长期会话；
- [ ] 当前任务状态在左侧实时可见；
- [ ] 手动与自动共用同一工作包后端；
- [ ] 成品必须包含图片、TXT 和生产记录；
- [ ] 生产页不再堆叠无必要的复杂筛选。
