# 团建工作台无人值守生产与分发路线图

日期：2026-08-07

## 最终目标

电脑开机后，团建工作台自动启动并恢复上次状态。系统自动识别可生产素材、账号额度、成品库存和在线设备缺口，持续完成生产与分发；用户只负责在手机端使用或发布作品。

同一能力必须同时支持三种入口：

1. 用户在软件界面手工操作。
2. 软件根据已保存的无人值守模式自动运行。
3. Codex、Claude、OpenClaw 等 Agent 通过稳定命令/API/技能触发。

三个入口必须调用同一套状态机和幂等命令，不能各自维护一份点击脚本。

## 核心闭环

```text
开机自启
  → 恢复队列、账号、额度和设备状态
  → 扫描可用素材
  → 自动选择最低使用次数素材
  → 上传 → 计划 → 回复 1 → 生图 → 文案 → 下载 → 归档
  → 更新成品库存
  → 检测在线设备及其作品缺口
  → 缺多少补多少并等待设备确认
  → 回到扫描与调度，持续循环
```

## 素材选择真源

- 文件夹名以 `.` 开头、隐藏文件夹、显式禁用或不完整的素材一律跳过。
- 文件夹名可解析出的数字表示历史使用次数；没有数字按 0 次处理。
- 自动生产优先选择使用次数最低的有效素材，同次数使用稳定顺序，避免每次重启后随机抖动。
- 素材领取、作品完成和失败回滚必须落盘；跨重启不得重复领取或错误增加次数。

## 账号生产单元

每个账号窗口独立保存：登录态、生产模式、模板、额度安全线、滚动周期、暂停/停止状态和当前任务。

- `manual`：只接受人工或明确 Agent 指令，全局调度跳过。
- `single`：单账号无人值守，持续使用当前账号直至真实限额或安全线。
- `rotate`：参与全局账号轮换；当前作品完整归档后才允许切换。
- `disabled`：未充值、未登录或人工禁用，所有自动调度跳过。

多账号轮换是单账号无人值守之上的调度层，不复制上传、下载或归档逻辑。

## 设备分发单元

每台设备独立保存：在线状态、目标库存、现有作品数、在途数量、最后确认时间和允许接收的作品标签。

- 设备离线：不推送，保留缺口。
- 在线且库存够：不推送。
- 在线且库存不足、成品库有匹配作品：只补缺口数量。
- 在线且库存不足、成品库也不足：产生生产需求，等待作品闭环后再推送。
- 推送必须收到设备确认后才扣减在途并更新库存，重试不得重复发送同一作品。

## 控制与可靠性

- 所有命令拥有稳定 ID，可安全重试；重复命令不得重复上传、回复 `1`、下载或分发。
- 状态变化先持久化，再执行外部动作；崩溃恢复时以网页证据、磁盘产物和持久检查点三方核对。
- 真实网页限额、登录失效、验证码、磁盘不足和设备传输失败使用不同故障分类。
- 短暂故障指数退避；完整性边界停止当前帖子但不覆盖现场；单账号不可用时按模式决定等待或轮换。
- 监测和统计只服务于定位卡点，不得抢占主链开发优先级。

## 分阶段交付门槛

### P0｜单账号真实主链

- 连续多套完成：选材 → 上传 → 计划 → `1` → 生图 → 文案 → 下载 → 归档 → 下一套。
- 覆盖重启续跑、半截计划、无响应、额度触顶、重复动作防护。

### P1｜单账号无人值守

- 开机自启、自动进入生产、自动选最低次数素材、工作时段控制、故障自愈。
- 用户不打开界面也能持续生产。

### P2｜多账号轮换

- 仅 `rotate` 账号参与；独立额度与冷却；全部冷却时等待最早恢复时间。
- 手动、单账号和禁用窗口不被全局轮换接管。

### P3｜库存驱动分发

- 自动发现在线设备、核对库存缺口、按标签补货、传输确认、防重复。
- 成品不足时把缺口反馈给生产调度器。

### P4｜Agent 控制面

- 提供查询状态、启动、暂停、恢复、指定账号/素材/设备、查看异常等稳定命令。
- 软件 UI、开机任务和 Agent 技能复用同一命令层。

### P5｜正式发布

- 每个大版本必须完成自动测试、真实桌面闭环、升级/回滚验证、源码提交与远端推送、安装包/便携包构建和发布说明。
- 未完成真实闭环的版本只能标记测试版，不得宣称无人值守可用。
