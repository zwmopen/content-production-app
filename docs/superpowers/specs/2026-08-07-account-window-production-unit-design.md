# 账号窗口独立生产单元设计

日期：2026-08-07  
适用版本：0.14.73 之后  
状态：设计已与用户确认，等待书面复核后实施

## 1. 目标

把每个 GPT 账号窗口变成互不干扰的独立生产单元。用户切换账号标签只改变当前查看对象，不改变其他窗口的运行状态。

每个生产单元独立拥有：

- 登录档案和网页会话；
- 生产模式（人工、选材后自动、单账号全自动等）；
- 当前模板及模板会话；
- 账号额度参数、周期计数和恢复时间；
- 任务队列、当前任务、检查点和失败状态；
- 暂停、停止、禁用与自动续跑状态。

目标使用场景：

- 账号窗口 A 使用单账号全自动，在后台持续生产；
- 账号窗口 B 使用人工模式，由用户选素材、上传并决定何时发送；
- 用户在 A、B 之间切换查看时，A 的任务不中断，B 的操作不修改 A 的队列；
- 后续允许两个或更多不同账号并行自动生产，但必须先通过双窗口可靠性验收。

## 2. 当前基础与缺口

现有代码已经具备账号隔离登录、按账号额度账本、按账号运行状态、账号模式记忆，以及多账号并行执行函数的基础。

尚未完成的隔离点：

- `gptAutoRunning`、主队列索引和部分自动设置仍是全局状态；
- 任一窗口运行时，其他窗口的模式切换和工作台人工任务会受到全局运行锁限制；
- 当前模式虽然能记在账号档案中，但模板、任务队列和完整模式参数还没有全部归属账号；
- 前台只突出“当前窗口”，没有同时展示各窗口的真实运行状态；
- 多窗口并行与单窗口主链仍共用部分调度状态，不能直接宣称混合手动/自动已可靠可用。

实施时不得通过复制整套旧状态变量解决问题，应建立明确的账号生产单元边界。

## 3. 核心模型

新增逻辑模型 `AccountProductionUnit`，以 `accountId` 为稳定主键：

```text
AccountProductionUnit
├─ identity：账号档案、名称、登录分区、禁用状态
├─ configuration
│  ├─ mode：当前生产模式
│  ├─ template：模板选择、模板会话 URL、模板初始化状态
│  ├─ workflow：该模式的步骤快照和参数
│  └─ quota：额度周期、上传额度、下一套停止线
├─ runtime
│  ├─ status：idle/running/paused/stopped/waiting-quota/failed
│  ├─ queue：该账号自己的任务队列与索引
│  ├─ currentTask：当前作品和安全检查点
│  └─ counters：附件数、计划页数、成图数、完成套数
└─ recovery：重启恢复、下次探测时间、最近错误
```

全局层只负责：

- 保存新账号的默认配置；
- 限制总并行数；
- 汇总状态和通知；
- 协调成品库写入锁，防止不同窗口混批。

全局层不得直接持有某个账号的当前任务、模式或队列真源。

## 4. 界面设计

### 4.1 日常主入口：当前账号的“生产模式与额度”面板

账号标签下方提供一个独立设置面板。切换账号标签时，面板内容跟随当前账号切换：

```text
当前生产单元：6日抛3
├─ 运行状态：正在生成第 4/676 套
├─ 生产模式：单账号全自动
├─ 当前模板：航拍路线节点封面
├─ 额度状态：本周期已生成 32 张 / 下一套停止线 45 张
├─ 预计恢复：23:35
└─ 生产设置
   ├─ 额度周期：3 小时
   ├─ 下一套停止线：45 张
   ├─ 上传额度：80 张
   └─ 当前套超过停止线：继续完成闭环（固定规则）
```

面板标题必须明确显示“正在设置：账号名称”，避免用户误改其他窗口。

“下一套停止线”不得命名为“最多生成张数”，因为它不允许中途终止当前作品。

### 4.2 快捷入口：账号标签右键

账号标签右键菜单增加“账号生产设置”，打开同一个设置面板并自动定位到该账号。

右键入口只是快捷方式，不建立第二份设置数据。

### 4.3 设置中心

设置中心提供所有账号的只读概览及快速跳转：

- 账号名称；
- 当前模式和模板；
- 本周期成图数与停止线；
- 当前状态和预计恢复时间；
- “打开账号设置”按钮。

批量页面不直接承载完整模式编辑器，避免多个账号参数同时展开造成误操作。新账号默认值单独放在“新账号默认设置”中。

## 5. 每账号额度规则

默认值：

- 统计周期：3 小时；
- 生图标称参考值：50 张；
- 下一套停止线：45 张；
- 上传额度：80 张；
- 默认按账号分别计数和恢复。

### 5.1 批次边界软上限

45 张只用于判断“是否允许开始下一套”，不得中断已开始的作品。

```text
开始下一套前：本周期实际成图数 < 45
  → 允许启动整套作品
  → 上传、计划、回复 1、生图、文案、下载、TXT、归档全部完成
  → 即使本套结束时累计达到 54 张，也算正常完成
  → 完成后进入额度等待，不启动下一套
```

如果开始下一套前已经达到或超过 45 张，则直接进入 `waiting-quota`，保留队列和登录状态。

### 5.2 计数口径

- 只把网页实际检测到并确认归属当前任务的成图计入生成数量；
- 发送申请、计划页数和预计图片数不直接当成已消耗图片；
- 当前作品生成期间跨过停止线，只记录状态，不改变当前工作流；
- 文案、下载和归档不消耗生图额度，必须继续完成；
- 新周期以该账号第一次真实进入生图阶段为锚点，周期到期后自动解除本地等待并执行网页探测。

### 5.3 网页信号仍是安全兜底

人工设置是提前停车线，不替代网页检测。以下真实信号可以让账号提前暂停：

- 网页明确提示上传、生图或速率限制；
- 只返回脚本、压缩包或代码解释器产物；
- 图片数低于完整作品安全线；
- 网页拒绝请求或反复返回生成阶段错误。

若真实限制发生在当前作品中途，保留当前作品检查点，额度恢复后继续该作品；不得把残缺图片打包归档，也不得启动下一套。

## 6. 模式与模板归属

每个账号分别保存：

- 当前模式；
- 模式工作流步骤和参数快照；
- 当前模板 ID、类型和模板会话 URL；
- 是否使用当前会话母版；
- 该账号最近成功初始化的模板证据。

切换账号时只刷新设置面板和可见网页，不修改其他生产单元。

模式变化只影响该账号下一项尚未开始的任务。正在运行的作品继续使用启动时冻结的模式和工作流快照。

## 7. 手动与自动混合运行

人工模式定义为软件辅助人工：

- 软件允许选择素材、模板并把附件和提示词准备到该账号；
- 是否发送、何时回复和何时进入下一套由用户控制；
- 人工任务仍记录素材归属和当前阶段，防止与自动窗口混批。

一个自动窗口运行时，另一个人工窗口不得再被全局 `gptAutoRunning` 禁用。只检查目标账号自身是否空闲或处在安全操作阶段。

用户在人工窗口的操作不得抢占自动窗口的 BrowserView、任务对象、下载绑定或归档目录。

## 8. 并行策略

第一阶段默认最大并行自动账号数为 2，并允许同时存在人工窗口。通过耐久验收后再开放 3 个及以上自动工作单元。

并行效率的适用边界：

- 不同实际 ChatGPT 账号可以获得明显产能提升；
- 同一实际账号的多个会话仍共享网页额度，不能把窗口数当作额度倍增；
- 每个账号一次只允许处理一套作品；
- 下载、文案和打包可以与另一个账号的生图等待并行；
- 归档使用任务级事务目录和成品库写入锁，禁止图片或 TXT 跨任务混合。

## 9. 故障隔离与恢复

- 账号 A 触顶，只把 A 标为 `waiting-quota`；账号 B 和人工窗口继续工作；
- 账号 A 输入框有草稿，只暂停 A，不阻塞其他账号；
- 某任务超时，只操作该任务的检查点，不推进其他账号的队列索引；
- 软件重启后逐账号恢复模式、模板、队列、停止线、计数、状态和下一次探测时间；
- 手动暂停、停止、禁用分别持久化，不能因切换窗口或重启丢失；
- 删除账号仍属于高风险操作，必须保持确认和登录数据清理边界。

## 10. 数据兼容

旧版全局状态迁移规则：

1. 当前激活账号接收旧队列、当前任务和旧模式；
2. 其他账号只继承新账号默认配置，不复制旧任务；
3. 已有每账号 `mode`、额度账本和窗口运行状态优先保留；
4. 迁移完成写入版本标记，重启不得重复导入；
5. 原有生产记录和成品路径不改名、不移动。

## 11. 验收标准

### 11.1 模式与切换

- A 设为自动、B 设为人工，来回切换 20 次后设置不串；
- 切到 B 后，A 的当前任务继续推进；
- B 的人工上传和发送不改变 A 的任务、素材、模板或下载结果；
- 切回 A 能看到真实阶段和累计额度。

### 11.2 额度闭环

- 账号在 44 张时允许启动一套 10 图作品；
- 该作品生成 10 图后继续完成文案、下载、TXT 和归档；
- 累计 54 张后不启动下一套，并显示预计恢复时间；
- 周期到期后只恢复该账号；
- 网页提前触顶时不归档残缺作品。

### 11.3 并行可靠性

- 两个自动账号各连续完成至少 3 套，成品文件不混批；
- 一个账号触顶或失败时，另一个账号继续；
- 自动账号运行期间，人工账号至少完成 1 套辅助人工流程；
- 重启后两个账号都从自己的检查点恢复；
- 全部行为有按 `accountId + taskId` 可检索的诊断日志。

## 12. 实施边界

- 不在当前运行作品中途热切换状态模型；必须等安全边界部署；
- 不把“单账号多对话巡检”混入本次首版，它继续作为独立后续模式；
- 不同时重构无关的生产页面、统计页面或分发模块；
- 首版优先实现一个自动窗口加一个人工窗口可靠并存，再验收两个自动窗口并行；
- 未完成真实双窗口闭环前，不把功能标记为稳定或默认开启。
