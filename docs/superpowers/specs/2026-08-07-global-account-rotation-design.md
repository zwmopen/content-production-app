# 全局自动切换账号生产设计

## 目标

在不改变单账号主链的前提下，增加一个全局账号调度层。每个账号窗口仍是独立生产单元，拥有自己的登录状态、生产模式、模板、额度安全线和冷却时间；全局调度器只在作品闭环后的安全边界选择下一个账号。

主链保持不变：自动选素材 → 上传 → 计划 → 回复 `1` → 生图 → 小红书文案 → 下载 → 创建作品文件夹并归档 → 下一套。

## 三账号 × 多对话的两层调度（后续阶段）

单账号多对话巡检完成并真实验收后，在现有全局调度器上增加两层串行调度，不新建第二套生产状态机：

1. 外层账号顺序固定为当前三个可用生产账号：`account-1 (1-zwmrpg) → account-2 (2-orlandocardozo706) → account-4 (4-日抛-embrace.ping)`；
2. 内层只遍历该账号标题命中“模板”且由工作台显式准入的对话；
3. 同一账号在额度安全线以内，按对话真实阶段续接并完成作品闭环；
4. 达到额度安全线、网页真实触顶或低产出边界后，完成在途作品再切换下一个账号；
5. 禁用、未登录、人工控制、人工暂停或仍在冷却的账号无条件跳过；
6. 所有账号均不可用时等待最早恢复时间，不创建额外并行任务；
7. 每个账号、每个对话分别保存阶段、素材绑定、模板绑定、图片额度与归档证据，禁止串号、重复上传和重复归档。

这不是 Codex 子代理并发生产。工作台是账号、网页和作品状态的唯一真源；AI Agent 只可作为启动、巡视、诊断和异常修复入口，不持有第二份生产队列。用户偏好由低成本 Agent“Luna”承担日常生产巡视，但当前工作台不得依赖某个 Agent 名称；运行环境不存在 Luna 时仍由工作台独立完成生产。

当前接入边界：账号 2 尚未加入正在使用的多账号名单；必须等两层调度自动测试与安全暂停复验完成后，才把 `account-2` 加入真实轮换，禁止为了展示配置而提前启动。

## 模板消耗与新账号初始化

- 当前先使用本地模板。模板必须有真实母版图片；空模板自动跳过。
- 为模板增加独立使用账本：使用次数少的优先，同次数按最久未使用优先；一次作品成功归档后才增加一次，失败或暂停不增加。
- 当前本地模板库有 16 个条目，其中 12 个含图片、4 个为空；在账本实现前不得宣称“自动把本地模板用完”。
- 在线模板库为空时不阻塞生产，继续使用本地模板。
- 老账号分享链接只能作为初始化参考或对话快照，不能假设新账号能原样继承并继续原会话。新账号优先走“V4.5 初始化提示词 + 本地母版上传”；分享链接可作为辅助参考，成功复制到新账号历史并通过生产就绪检查后，才登记为该账号自己的在线模板。
- 在线模板必须保存目标账号、来源链接、复制后的新会话 URL、初始化版本和最后验证时间；只读分享页不得直接领取生产任务。

## 两层模型路由

必须区分 AI Agent 控制模型与 ChatGPT 网页生产模型：

- Agent 控制模型：只负责启动工作台、只读巡视、诊断和提交修复。用户偏好优先使用低成本的“Luna”；若当前 Agent 平台未提供 Luna，明确降级到可用 Agent，不改变工作台生产配置。
- 网页生产模型：每个 ChatGPT 账号窗口独立保存 `沿用当前模型` 或 `指定模型`。接单前读取页面当前模型并校验；指定模型在该账号不可用时，按该账号设置选择“沿用当前可用模型”或“跳过该账号”，不得静默改用未知模型。
- 本地 API 生图/文案模型属于另一条本地生产链，不能与 ChatGPT 网页模型混用同一字段。
- 首版先实现模型状态显示和只读校验；自动点击模型选择器必须单独回归 ChatGPT 页面结构、账号权限差异和生成中切换保护后再开放。

## 模式与参与规则

每个账号窗口独立选择生产模式：

- 手动生产：只接受人工操作，默认不参与全局轮换。
- 单账号全自动：只在自己的窗口连续生产，触顶后自己等待，不参与全局轮换。
- 全局轮换：加入全局调度候选池，由调度器串行选择。

账号满足以下全部条件才可参与全局轮换：

1. 账号窗口未被禁用；
2. 账号自身模式为“全局轮换”；
3. 登录与网页生产环境可用；
4. 当前不在额度冷却期；
5. 当前没有人工暂停或停止标志。

隐藏标签不等于禁用。隐藏但仍启用且设置为全局轮换的账号可以参与；被禁用的账号无条件跳过。

## 额度安全线

每个账号独立保存：

- 生图安全上限，默认 45 张；
- 滚动周期，默认 3 小时；
- 本周期第一次确认生图的时间；
- 本周期已确认生成的图片数；
- 最早恢复/探测时间。

安全线只在作品闭环后判定，绝不强行中断正在进行的作品。例如账号累计 44 张时已经启动一套 5 张作品，该套仍需完成 5 张图片、文案、下载和归档；闭环后累计为 49 张，再切换账号。

本地安全线是主动轮换依据，网页真实限额、低产出或明确重试限制是提前轮换依据。两者任一命中，当前账号在安全检查点进入冷却。

## 调度算法

全局调度器保持单一活动作品，不并行向多个 ChatGPT 窗口注入素材：

1. 从上次账号位置开始查找下一个可用账号；
2. 当前账号未达到安全线时持续使用，不按每套作品轮换；
3. 当前作品完整归档后更新真实生图计数；
4. 达到安全线或网页真实触顶后，将账号标记为冷却并切到下一个可用账号；
5. 到账号列表末尾后循环到第一个账号；
6. 所有参与账号都在冷却时，暂停新作品，等待最早恢复时间；
7. 到点后只用下一条素材做自动探测，成功则恢复该账号，仍触顶则重新计算短间隔探测时间；
8. 队列、账号游标、冷却状态和当前作品检查点均跨重启保存。

账号切换不得改变用户当前正在查看的标签，也不得把一个账号已开始的作品迁移到另一个账号。任务从上传开始就永久绑定到账号，直到归档或明确失败。

## 界面

账号自己的设置面板提供：

- 生产模式：手动生产 / 单账号全自动 / 全局轮换；
- 生图安全上限；
- 滚动周期；
- 是否禁用；
- 当前周期已生图数量、剩余额度估算和预计恢复时间。

全局区域只展示轮换总状态：当前账号、下一个候选账号、参与账号数量、冷却账号数量以及最早恢复时间。全局入口不重复维护账号额度，避免出现两份互相冲突的设置。

## 全局轮换设置层（待当前主链实测通过后逐项实现）

设置中心需要把调度策略做成可配置项，但不得复制或改写单账号主链：

- 运行轮数：`1 轮`、`N 轮`、`无限循环`。一轮定义为所有参与账号都完成本轮额度消耗，或经过真实探测后进入冷却/不可用；测试默认只跑一轮并自动停止。
- 工作时段：允许配置每天开始与停止启动新作品的时间；已开始作品仍完整收尾。
- 账号额度：每账号独立设置生图安全线、滚动周期、附件安全线和探测间隔，默认 `45 张 / 3 小时 / 80 附件`。
- 恢复参数：无回复恢复等待、计划恢复次数、普通重试次数、重试间隔和最终超时均可配置，并提供经过实测的安全默认值。
- 会话策略：`新建会话并初始化` 或 `延续账号已绑定会话`。前者在账号开始生产前创建新 ChatGPT 会话并初始化模板；后者直接沿用已经调教好的生产对话，不重复注入母版。
- 模板来源：本地文件夹模板需要先上传母版并完成初始化；链接模板直接打开已调教的 ChatGPT 会话链接，通过就绪检查后发送素材。
- 模板选择：选中一个模板时，全部参与账号统一使用它；选中多个模板时，账号按可追踪的随机分配使用其中一个，并记录本轮实际模板，避免重启后漂移或同一作品中途换模板。
- 提示词版本：当前用户提供的《轮播母版迁移器 V4.5｜完整版总提示词》登记为待导入的本地模板规则候选；在独立回归和真实一套验收前，不直接覆盖正在运行的 V3.6 主链。

以上选项必须保存到持久化设置并真实影响调度器；未实现的控件不得提前展示为可用功能。

## 异常与恢复

- 当前作品生成中：完成整套闭环后再切换。
- 网页提前触顶：保留当前素材检查点，不上传下一套；切换账号后由新账号领取同一未完成素材的安全重试版本。
- 账号未登录或页面不可用：标记该账号暂不可用并选择下一账号，不禁用或清理登录档案。
- 用户手动暂停/停止账号：调度器不自动唤醒该账号。
- 软件重启：从持久化的账号游标、任务检查点和冷却时间恢复；不得重复上传、重复发送 `1` 或重复归档。

## 验收标准

自动化测试至少覆盖：

1. 手动生产账号不参与全局轮换；
2. 单账号全自动账号不参与全局轮换；
3. 被禁用账号不参与全局轮换；
4. 只有全局轮换账号进入候选池；
5. 44 张时启动的 5 张作品完整闭环到 49 张后才切换；
6. 当前账号未触线时连续使用，不每套轮换；
7. 达到安全线后切换到下一个可用账号；
8. 所有账号冷却时等待最早恢复时间；
9. 冷却到点后自动探测并恢复；
10. 重启后账号游标、额度账本、冷却时间和未完成任务保持一致；
11. 手动切换可见标签不影响后台任务绑定；
12. 网页真实限额优先于本地安全线。

桌面验收使用两个可用账号和一个禁用账号，先把测试安全线临时设低，在不消耗大量额度的情况下验证完整轮转；验收完成后恢复默认 45 张 / 3 小时。

第二阶段耐久验收按用户授权使用账号 `1 / 2 / 4` 跑一轮：逐账号生产到各自 45 张安全线或真实网页限额，完成在途作品后切换；所有参与账号完成一轮后自动停止，不进入无限循环。全过程记录每账号接单数、计划恢复、生成数、归档数、限额原因和切换证据。

## 实施顺序

1. 收口当前计划解析与安全重试修复，完成全量测试；
2. 将账号参与资格和安全线判断提取为可测试的纯逻辑；
3. 测试先行接入全局轮换调度器；
4. 完善账号设置与全局状态展示；
5. 更新版本、变更日志、交接文档和回归清单；
6. 在当前作品安全闭环后暂停并完整重启 Electron；
7. 验收小猫、单窗口设置、计划恢复与全局轮换。
