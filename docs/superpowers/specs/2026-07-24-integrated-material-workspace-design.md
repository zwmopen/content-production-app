# 双栏素材生产与外部能力兼容集成设计

状态：待用户书面复核  
日期：2026-07-24

## 目标

把散落在本地目录、真实 ChatGPT 网页、油猴脚本、VBS、PowerShell 和共享 Skill 中的人工操作统一归口到团建内容工作台，同时保留已经跑通的执行链路。

核心原则是：

> 入口全部归进工作台，能力尽量复用原件，源码不制造第二份。

## 已有能力真源

- ChatGPT 网页增强：`chatgpt-conversation-tree` 1.12.1。
- 网页到本地协议：`cgpt-workpkg://run` 与 `cgpt-workpkg://configure`。
- 作品包执行：一键 GPT 作品包 VBS/PowerShell 1.4.1。
- 手机传输执行：`device-folder-transfer`。
- 团建素材、成品和发布空间：江湖有旅人主项目目录。

这些能力继续由各自项目维护。工作台不得复制出第二份可独立修改的源码。

## 界面结构

左侧工作流栏保留：

1. 素材生产
2. 作品集
3. 分发功能
4. 发布调度（规划中）
5. 发布复盘
6. 设置

删除“总览”，启动后默认进入“素材生产”。

素材生产采用双栏结构：

- 左侧：真实本地素材目录树。
- 右侧：真实 ChatGPT 网页工作区。

左侧目录树按硬盘层级展开，显示分类文件夹和帖子文件夹。每个帖子文件夹右侧提供“传 GPT”入口。点击帖子后，工作台建立当前任务绑定，并激活对应 ChatGPT 母版会话。

右侧网页继续使用现有登录状态和油猴脚本，保留对话树、提示词库、图片整组下载和一键作品包入口。

## 运行形态

第一阶段使用混合式 Windows 工作台：

- 本地软件负责左侧目录树、工作流栏和状态。
- 专用真实浏览器窗口负责右侧 ChatGPT。
- 软件负责打开、激活和排列窗口，使两部分形成稳定双栏。

普通本地网页不能可靠地通过 `iframe` 嵌入 ChatGPT，因此不得用静态聊天界面冒充真实接入。后续若迁入 WebView2 或其他内嵌浏览器，必须先验证登录、用户脚本兼容、下载、本地协议和多会话隔离。

## 联动数据流

```text
本地帖子文件夹
  → 工作台创建当前任务绑定
  → 激活指定 ChatGPT 会话
  → 把素材交给真实网页
  → 原油猴脚本下载图片
  → cgpt-workpkg:// 调用现有 VBS/PowerShell
  → 作品包和作品集写回原成品库
  → 工作台重新扫描并更新状态
```

工作台只保存任务标识、路径、会话地址、阶段状态和错误信息，不复制图片正文或浏览器账号凭据。

## 渐进升级方式

每项外部能力采用三阶段迁移：

1. **直接调用**：保持原脚本不变，由工作台统一入口。
2. **适配器联动**：增加结构化参数、进度和结果回传，不复制执行逻辑。
3. **稳定后内建**：只有当接口、测试和回退方案成熟时，才把能力迁入软件模块。

旧入口在迁移验收完成前保留。任何内建替换失败时，应能回到原油猴、VBS 或 Skill 流程。

## 任务绑定与安全

- 一次只能有一个明确的当前生产任务。
- 上传、下载、文案和作品包必须绑定同一任务 ID。
- 切换帖子或会话时显示当前绑定对象。
- 不读取或保存 ChatGPT Cookie、密码和对话全文。
- 不在未确认时覆盖已有文案或成品。
- 外部脚本失败时保留素材和任务状态，允许恢复原手动流程。

## 本轮实施边界

下一轮只实现：

- 删除“总览”并让素材生产成为默认入口。
- 增加“发布调度（规划中）”入口。
- 把素材生产改成左侧树状素材区和右侧真实网页连接区的布局基础。
- 复用现有素材扫描和脚本入口，不重写 VBS/PowerShell。

真实浏览器窗口停靠、自动上传、网页事件回传和任务持久化按独立里程碑逐步接入，不在一个版本中假装全部完成。

## 验收标准

- 用户从工作台能看见与硬盘一致的素材树。
- 帖子文件夹可展开，且“传 GPT”入口与对应路径绑定。
- 右侧明确显示真实网页连接状态，不显示伪造聊天内容。
- 现有油猴下载、本地协议和一键作品包仍能按原方式使用。
- 关闭新工作台后，原浏览器和 VBS 手动流程仍然可用。
- 页面不存在宣称已接入但无法操作的假按钮。
