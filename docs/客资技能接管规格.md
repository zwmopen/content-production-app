# 团建客资统计技能｜接管与安装规格

> 本文件是 `wechat-teambuilding-conversion` 的交付门禁实例。它描述如何让新的用户或新的 AI 安全接手，不保存个人密钥、微信登录态、完整聊天或原始敏感媒体。

## 1. 接管目标

接手者只需要完成三类明确动作：

1. 安装技能包并确认本机运行环境；
2. 在 WeFlow 和飞书入口完成自己的授权；
3. 确认自己的身份、客资资格阈值、目标表和来源规则。

之后系统应能自动完成：读取授权范围内的证据、判断资格、合并和去重、生成预览、写入目标表、回读核验、推进安全水位和输出异常报告。

## 2. 交付边界

| 资产 | 当前交付方式 | 新接手者要做什么 |
|---|---|---|
| 通用 Skill | `D:\AICode\AI\skills\技能包\技能\wechat-teambuilding-conversion` | 安装/发现，不改通用规则 |
| 专属角色配置 | `D:\AICode\AI\private-config\agents\jianghu-teambuilding-lead` | 复制模板后替换自己的身份和目标表映射 |
| 密钥和登录态 | 凭据管理器、WeFlow/飞书本地授权 | 重新授权，不复制旧值 |
| 运行状态 | 运行数据目录中的状态摘要和报告索引 | 选择从零开始或经人工确认恢复水位 |
| 外部系统 | WeFlow、飞书多维表/表格 | 只授权必要范围，并允许回读验收 |

## 3. 一键接管状态机

```text
发现技能
  → 检查 SKILL.md、脚本、引用和版本
  → 检查 profile/字段映射/恢复入口
  → 检查 WeFlow 本地服务和飞书 CLI
  → 检查授权状态
  → 读取目标表结构（只读）
  → 试跑已脱敏样本或小范围预览
  → 验证正例/反例/重复/冲突
  → 申请启用正式写回
```

任一硬门禁失败，状态必须停住，不允许自动跳到正式写回。

## 4. 客资业务验收口径

### 正常路径

- 读取授权 WeFlow 会话中的本人证据；
- 同步识别截图、转发聊天记录、群中“已拉群”或后续补充消息；
- 以消息 ID、媒体哈希、联系方式和业务指纹合并去重；
- 只保留达到当前项目资格阈值的团队客资；
- 联系方式优先级由专属配置声明，无法确认时保留为待复核，不把昵称猜成账号；
- 来源、日期、地点、人数和简单要求按目标表字段映射写入；
- 写入后逐条回读，全部通过才推进水位。

### 必须进入人工复核

- 不能确认是否为本人发送或本人客资；
- 同一个客户存在多个联系方式或多个群归属；
- 只有昵称，没有可核验的账号、原始 ID 或手机号；
- 证据来自转发、跨群或跨平台，时间和身份无法闭合；
- 表格已有记录但业务指纹冲突；
- 资格阈值、来源默认值或备注格式出现新规则。

### 必须阻断

- WeFlow 或飞书未授权；
- 目标表结构无法读取；
- 写入成功无法回读；
- 运行水位缺失且没有恢复边界；
- 需要通过猜测补齐账号、身份或业务字段；
- 当前操作会影响同事数据、其他项目或未授权会话。

## 5. 检查项与责任人

| 检查项 | 通过证据 | 失败状态 | 触发谁 |
|---|---|---|---|
| 技能源存在 | `SKILL.md` 和引用文件可读 | `needs_developer` | 技能维护者 |
| 运行时兼容 | 目标 AI 能发现技能、脚本版本可用 | `needs_developer` | 开发/维护者 |
| 私有配置完整 | profile、字段映射和恢复入口存在 | `needs_user` | 当前用户 |
| WeFlow 健康 | 本地服务可达，授权范围可读 | `needs_user` 或 `needs_developer` | 用户/连接器维护者 |
| 飞书目标表可读 | 目标资源和字段结构回读成功 | `needs_user` 或 `needs_admin` | 用户/管理员 |
| 业务规则确认 | 阈值、本人范围、来源默认值明确 | `needs_user` | 业务负责人 |
| 试运行 | 候选、排除、重复和冲突有报告 | `blocked` | 技能维护者/业务负责人 |
| 写回验收 | 写入后字段逐条回读一致 | `blocked` | 技能维护者 |

## 6. 新接手者看到的界面

不要让用户理解内部术语，界面只显示：

- “技能文件已安装”；
- “还需要你授权 WeFlow”；
- “还需要你选择目标表”；
- “检测到 2 条身份冲突，请你确认”；
- “试跑通过，尚未写正式表”；
- “正式写回已启用”。

技术日志可以保留 `check_id`、状态码、路径和版本，但不显示秘密和完整聊天正文。

## 7. 当前实例的恢复规则

- 技能源和运行副本必须区分，不能根据文件修改时间猜最新；
- 运行状态缺失时只读核对历史表和 WeFlow 边界，不能直接从头补写；
- 回读失败时保持旧水位，状态标记为 `partial` 或 `failed`；
- 换电脑时恢复技能、配置模板和报告索引，WeFlow/飞书重新授权；
- 恢复后必须重跑一个正例、一个低于阈值反例、一个重复例和一个联系方式冲突例。
