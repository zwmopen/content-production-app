# 架构

## 2026-08-25 三源阶段证据与工作流 variant（0.19.200）

```text
页面 DOM 检测 ─┐
作品持久检查点 ├─> 身份门（account/browser/task/conversation）
会话事件日志 ─┘        └─> 阶段共识 -> 唯一安全动作
```

- 机器阶段序列为 `session-init -> template-learning -> session-ready -> material-uploaded -> plan-ready -> confirm-sent -> images-generating -> images-ready -> copy-requested -> copy-ready -> downloaded -> packaged -> archived`。
- 新阶段取“持久旧阶段”与“当前证据阶段”的更靠后者；文案/成品证据不可被虚拟滚动或懒加载后重现的旧计划覆盖。
- `HIGH_CONFIDENCE` 才可写；`MEDIUM_CONFIDENCE` 只可检查/导航/恢复；`LOW_CONFIDENCE` 只保留状态；`STATE_CONFLICT` 禁止发送并记录冲突。
- `workflowVariant` 与用户界面的 `productionMode=single` 分离；前者决定 `fresh-session-fixed-template` / `legacy-v1` 实验链，后者仍表示单账号连续生产。

## 2026-08-23 图文工作台多窗口自动生产恢复链（0.19.117）

- 每个自动账号窗口独立持有队列、检查点、原始 `/c/...` 会话 URL、阶段起点、最后真实进展和恢复计数；一个窗口恢复或重建不暂停其他窗口。
- 页面证据按“归档完成 → 文案完成 → 图片达到计划数 → 计划完成 → 生图中 → 未知”解释。文案/归档证据是封口边界，恢复时直接进入下载、打包、归档，不再补图或重发出图计划。
- 每步使用有限截止：上传 2 分钟、计划 8 分钟、生图 15 分钟、文案 8 分钟、下载 10 分钟、归档 3 分钟；20 分钟只用于识别无进展并升级恢复，不是整套作品失败截止。
- 单窗口恢复共用一把锁：同一原对话每 10 分钟最多刷新 2 次，随后释放旧渲染器并重建同账号嵌入浏览器；全部自动窗口都不可用时，检查点落盘后才有序重启工作台，始终回接原 `/c/...`，不回到 ChatGPT 首页。
- 自动生产时段为北京时间 08:00–02:00；每分钟运行循环负责队列，每小时健康审计负责直接执行恢复。用户暂停/停止、手动模式、登录/验证码和真实额度等待仍是不可越过的人工/平台边界。

## 2026-08-18 GPT 全自动持续恢复闭环（0.19.31）

- 每个账号窗口的 `queuePaused` 是可恢复检查点，不是人工暂停。调度器只把显式用户暂停/停止、手动模式和外部登录验证当作硬边界。
- 普通 `production-failed` 通过自动恢复策略处理：网页/桥接临时故障按步骤截止时间、单轮有限预算和持久化恢复次数执行有界重试；确定性工作流故障达到有限恢复预算后将当前作品顺延，连续多轮仍失败则自动隔离待复核，不能阻塞同账号其他任务，禁止无限退避等待。
- `quota`/真实低产出上限不进入普通重试：由账号专属 `nextProbeAt` 驱动持久化额度提醒；探测时间落在工作时段外时保留额度检查点，推迟到下一个工作时段。
- 工作时段由窗口调度器统一守门，所有恢复计时器都先检查 `07:00–02:00`；跨应用重启依靠每账号队列、检查点和额度账本继续，而不是依赖内存中的一次性定时器。

## 2026-08-15 统一 AI / 语音 / 界面动作层

- `public/workbench-command-bus.js` 是前端入口的动作协议：按钮、文本助手、AI 调用和内置语音识别统一提交 `actionId + args + source`，再由已登记处理器调用既有业务函数；动作不能直接变成任意 JavaScript、命令行或路径。
- 当前已接入 `assistant.text`、`workspace.refresh`、`workspace.context`、`gpt.browser.refresh`、`gpt.diagnostic`、`gpt.continue`、`gpt.toggle-pause`、`gpt.retry` 和 `gpt.skip`。生产按钮与助手/语音调用的是同一动作，不再复制一套“AI 专用生产逻辑”。
- `/api/workbench-control/context` 只读白名单运行状态、GPT 日志和有限源码片段；源码入口和日志文件固定在服务端映射中，不能由自然语言传入任意文件路径。返回内容用于诊断和下一步动作，不替代真实运行数据真源。
- 现有“鼠标快速语音打字”技能仍是外部输入辅助；它可以把语音变成文字，但不负责工作台执行。内置语音识别与外部技能最终都应调用 `window.workbenchControl.voiceText()`，从而复用同一动作总线。
- 业务状态仍由各域真源维护：GPT 队列由 Electron/运行时镜像负责，分发由服务端和设备账本负责，素材/成品由真实目录负责，助手日志只做展示和审计。统一动作层负责调度，不把展示日志当作状态真源。

## 2026-08-14 传输层路线：LAN V2 默认，P2P/远程中继分层

- 当前电脑到手机的真实主链是 UDP `45834` 发现 + HTTP `45833`/TCP 上传 + SHA-256 + `commit`；同一 Wi‑Fi 下数据面已经是直连，不用因协议命名改成 WebRTC。
- Android 已有局域网设备间 `peer-forward` 中转骨架（`relay-queue`、过期时间和 hopLimit），但它不是公网远程中继，电脑主链也不依赖它。
- 新传输只能作为能力协商后的可选层：`lan-v2`（默认）→ `peer-forward`（局域网转发）→ `direct-peer`（未来实验）→ `relay`（跨网后置）。任何新层都必须可回退到 `lan-v2`，保留现有校验、提交、去重和失败恢复。
- 详细决策、接口和验收门槛见 `docs/TRANSPORT-ROADMAP.md`。在完成真实基线测量前，不替换当前稳定链路。

## 2026-08-14 电脑端与手机端的通用协议边界

- 电脑端是唯一调度真源，手机端只提供能力：`discover`、`info`、`inventory`、`transfer`、`commit`、`heartbeat`、`appVersion`。调度器按能力和字段判断，不按品牌名称判断。
- 接收端必须能上报 `workCounts` 分类库存；只有总库存而没有目标分类时，电脑端保持 `inventory_unknown`，不得猜测精准/泛库存。
- Android（小米/红米、VIVO、华为）共用同一协议和数据迁移规则；品牌差异放在网络、电源、安装和系统权限适配层。Apple 使用同一协议模型，但 iOS 接收端尚未在本项目中实现，不能把 Android APK 视为 Apple 支持。
- 升级采用能力向后兼容：新字段可选、旧字段仍可读；保留 application id、签名、接收目录和作品索引。协议变更必须先通过手动传输，再通过自动补货回归。
- 自动分发状态机的准入条件固定为：设备已发现、在线可达、首次授权已完成、目标分类库存已知且低于阈值、存在未成功发送的候选 workId。任何条件未知都不发送。

## 0.13.0 工作台调度与扩展执行

- 工作台是本地事实层：扫描素材/模板目录、计算组合、维护账号额度、持久化任务、校验成品、归档素材和备份设置。
- 浏览器扩展是网页执行层：只在真实 ChatGPT 页面内完成附件上传、发送、回复稳定检测、图片与文案提取和下载。自动模式与网页消息旁的手动下载按钮复用同一底层能力。
- 模板初始化与素材生产是两类任务。每个已选模板对应一个新会话；初始化成功后，该会话串行处理所有已选素材。未选择模板时不会新建会话。
- 每套作品的状态机为：排队、初始化模板、上传附件、等待计划、自动确认、生成图片、请求文案、下载、打包校验、素材归档、完成。失败记录阶段和检查点，重试从失败阶段继续。
- 每账号账本按滚动三小时事件计算上传与生成消耗。调度器只接纳能完整放入剩余额度的任务，超额任务进入等待；网页限流、验证和登录过期会覆盖本地估算并暂停。
- 素材归档只有一个入口：服务端确认批次图片、TXT 和成品目录全部存在后，才允许在配置素材根目录内部移动帖子文件夹；同名目标永不覆盖。
- 原生 `WebContentsView` 在工作台弹窗或其他功能页打开时隐藏，避免压住 DOM 弹窗。账号初始化使用共享 Promise，防止快速切换造成重复网页实例。
- GPT 登录分区不进入普通 JSON 或云端备份。本机恢复点使用“写入待办 → 重启 → 网页分区尚未打开时复制/恢复 → 再启动”的顺序，避免热复制被锁定的 SQLite/Cookie 文件。

## 0.12.2 GPT 网页自动生产链路

- Electron 主进程使用 `WebContentsView` 承载真实 `https://chatgpt.com/`。每个账号使用 `persist:teambuilding-gpt-production-<id>` 独立持久分区，Cookie、登录状态、浏览历史和页面导航互不共享。
- 渲染页负责素材/模板树、勾选状态、账号切换与串行队列。一个母版映射多个素材时，每个素材形成一个独立任务；上一组真实完成或按设置跳过后才进入下一组。
- 典型附件为母版前两张图（封面与通用内页）加当前素材文件夹中的图片、TXT/Markdown；提示词合并长期母版规则、文件角色和当次补充要求。
- 现有浏览器扩展在嵌入态不渲染重复生产舱，但负责原生附件上传、计划检测、自动确认、新图片检测、文案检测、精确批次下载和结果回传；本地文件仅允许从工作台授权接口读取。
- 主进程与网页扩展通过一次性任务编号和 DOM 事件桥接。成功、失败、取消都必须回传；未登录、无附件入口或超时会在工作台明确失败，不能伪装为已送入。
- 每组下载生成唯一批次号，文件名携带批次、序号和总数。服务端只允许该批次进入工作包脚本，并在返回成功前复核图片张数、TXT 和输出目录，避免下载目录旧文件串包。
- 生产间隔由页面设置给出最短和最长秒数，渲染页在两组之间随机等待。该等待只调节正常队列节奏；平台验证、登录失效和限流由扩展识别并暂停。
- 工作台不读取、导出或注入 Google/OpenAI 凭据。Cookie 只存在 Electron 用户数据分区，Git、诊断与业务日志均不记录。
- 打包应用优先加载 `integrations/gpt-production-extension` 内置运行快照；源码开发优先加载独立扩展仓库。同步脚本只复制 manifest、后台脚本、内容脚本、样式和网页助手运行文件，不复制测试或浏览器数据。

## 0.12.1 校准优先生产状态机

- `/api/production/run` 固定以 `runScope=calibration` 启动，只允许计划中第一套作品的第一张 P1 进入生图函数。
- 首图成功后任务进入 `calibration-ready`，结果、输出目录与请求审计均持久化；`/resume` 只有在该状态下才把范围切换为 `full`。

## 0.11.6 增量备份与短期任务表面

- `webdav-backup.js` 提供目录逐层建立和文件流式 PUT；服务端不把大文件一次性读入内存。

- 流量转化资源代理在改写 `/api/*` 时保留嵌入页自身 fetch 包装器的原始判断，避免 `/conversion-integrated/conversion-integrated/api/*` 双前缀。

- `device-presence.json` 仅在运行数据目录保存最近发现的设备摘要；本轮未回包的设备最多保留 10 分钟并标为“最近在线”，实际发送仍由共享 Skill 重新发现和连接。

- 局域网设备发现记录被标准化为 `transport=wifi`，前台从真实发现状态生成连接标签；USB、远程保留独立状态位，未获得底层事实时不得显示为在线。
- `transfer-progress.js` 从底层完成 JSON 中提取实际 `transport`，完成任务可显示本次传输使用的协议。
- 发送闭环顺序保持为：原子 claim → 设备接收确认 → 追加 `device-usage-log.csv`（含传输协议）→ 完成 claim → 原作品集移动到公众号目录。历史记录即使遇到入口误建，也会阻止再次进入手机待发送库存。

## 0.9.3 文件夹即状态

- `distribution-data.js` 同时识别发布空间中的 Junction 和真实目录，并输出 `workflowStage`。
- 手机分发进程只有在接收端提交成功后，才把原始作品目录移动到 `发布空间/公众号`。
- `POST /api/distribution/mark-used` 将公众号原始目录移动到 `发布空间/已使用` 并追加可审计日志。
- 外部手动移动后，下一次快照直接按目录位置重算阶段；不存在需要同步的第二份阶段台账。

## 0.9.2 素材全局索引

- `material-global-index.json` 保存紧凑全库条目、分类数量、母标签/次数分面和待核对历史证据。
- `GET /api/extension/material-index` 第一次调用或素材根变化时启动异步逐分类扫描，轮询返回进度；每个分类扫描完成后让出事件循环。
- 历史证据来自 `01-素材库/素材链接记录.csv` 与 `04-技能库/运行记录/制作日志.csv`，以事件键幂等导入元数据台账。
- 全库索引不保存附件内容；真实上传仍由分类懒加载接口读取。

## 0.9.1 分类按需加载与素材身份层

- 素材文件夹身份由文件系统目录身份派生为 SHA-256；同卷改名或移动后保持不变，内容相同的两个目录也不会共用身份。
- `material-hash-cache.json` 缓存路径对应的目录身份和文件夹哈希。
- `防重复账本/material-metadata-ledger.json` 以文件夹身份哈希为键保存人工母标签与使用次数。
- 图片、TXT、Markdown 的聚合内容指纹仍由使用台账保存，只用于内容防重，不再充当文件夹身份。
- `/api/materials` 只为用户展开的分类计算并返回元数据，避免打开工作台时全库同步哈希。
- `materialCategoryIndex()` 只读取素材根目录的直接子目录；`materialCategoryCache` 按分类路径独立缓存递归结果，顶层签名变化时不会复用已不存在的分类。
- `/api/dashboard` 只装载状态中当前分类，`/api/materials` 无分类参数时只返回轻量索引；两条入口不再先构造完整素材库再隐藏未展开内容。

```text
项目推进（素材/模板/成品/生产记录/发布空间）
              ↓ 只读为主
工具开发/teambuilding-workflow-dashboard/src
              ↕
运行数据/江湖有旅人/图文生产控制台
              ↑
AI/skills/技能包/技能
  ├─ teambuilding-xhs-workflow（生产方法）
  └─ device-folder-transfer（分发执行与安全规则）

独立浏览器扩展 teambuilding-gpt-production-extension
              ↓ 仅本机接口
   授权目录 / 文件流 / 生产去重只读状态
```

`server.js` 提供仅监听本机回环地址的 HTTP API、静态页面、设备自动刷新、可恢复传输任务进度/取消、扩展只读协作接口和分发 Skill 白名单调用；`lib/transfer-progress.js` 把底层输出转换为用户可见阶段和百分比；`lib/dedup-ledger.js` 区分生产历史与分发历史；`lib/distribution-data.js` 从 Junction、台账和 CSV 日志计算作品集状态；`public/` 是工作流控制台；`desktop/` 承载本地界面；`mcp/` 保留聚光数据调用入口。

生产防重与分发防重是两套独立事实：生产历史库按整组图片 SHA-256 确定重复，并用 64 位 dHash 做近似预警；分发防重继续使用 claim、使用日志和入口状态。两类数据都不复制进公开源码。

手机发送、接收确认和 Junction 安全删除不在工作台中重写，而是调用 `device-folder-transfer`。工作台负责任务选择、输入校验、系统内最终确认、进度、取消、结果呈现和状态刷新；普通文件传输与作品包补笔记使用同一设备发现、任务表现和传输真源。软链接兼容层属于执行内核，不在前台显示。

作品包防重采用三层互锁：发送前在 `.distribution-claims/` 原子创建独占 JSON 占用；接收成功后写入 `device-usage-log.csv`；最后删除对应活动 Junction。任何一层显示已占用/已使用，随机与指定分发都拒绝再次发送。

平台资格分为两个使用组：小红书与抖音是同一手机组，候选必须同时存在两个有效同源入口，使用一次后整组退出；公众号是独立组，其入口与手机组互不消耗。
# 0.9.6 本地生产任务

# 0.19.23 朋友圈月度采集调度

朋友圈自动化现在分成两条互不混淆的定时链路：每日发布准备由 `scheduleWindowStart` / `scheduleWindowEnd` 驱动，当前为北京时间 `10:00–12:00` 窗口，窗口内尽早执行；月度采集由 `collectionScheduleEnabled`、`collectionScheduleDay` 和 `collectionScheduleTime` 独立驱动。两套时间都由本地 `app-settings.json` 持久化并可分别修改。每日链路使用日期加窗口的幂等键，超过窗口不补发；月度链路读取同一 `moments.libraryRoot`，调用现有 WeFlow 采集器并复用其逐条落盘、去重和标签整理，不创建第二个素材库。每月运行键和最近回执写入该目录的 `state/collection-scheduler-state.json`，因此服务重启不会重复采集。
