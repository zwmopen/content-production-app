# 团建生产线：一页使用说明

更新：2026-10-10 20:00（北京时间）｜对应本地开发 2.6.33-dev，尚未发布到所有桌面实例。当前生产只按两条线称呼：在线模式（GPT 网页/CDP）与本地模式（Codex 客户端）；CDP A/B 是在线模式下的两个实例。复刻重组、随机模板、固定模板是两条产线共用的三种做法；Gemini 已停用，仅保留历史只读入口。真实端到端验收状态仍以实际调用、成品和交付回读为准。

## 记住这一句

**一套作品 = 一个完整素材文件夹 + 一条产线 + 一种做法。** 不从别的素材夹借图，也不把几个作品混成一套。

## 先选产线，再选做法

**产线**回答“由谁来做”：

- **在线模式（GPT 网页/CDP）**：网页生产；实例 A/B 各自独立，A 的成功不能证明 B 也成功。
- **本地模式（Codex 客户端）**：由当前 Codex 客户端对话执行；工作台目前只能登记请求，不能代替当前对话调用原生生图工具。
- **Gemini 历史记录**：团建生产已停用，只读查看旧记录，不计作当前生产线。

**做法**回答“按什么样子做”：

1. **复刻重组**：参考原作品结构，按当前素材重新组织。
2. **随机模板**：从真实、适用的模板候选中为整篇选一个模板。
3. **固定模板**：指定一个模板 ID，整篇按它的 P1 封面和 P2 内页规则制作。

“整套模板迁移”和“只补封面”是任务类型，不是上面三种做法之一。迁移时，每张有效源图各做一张；只补封面时不重做内页。

## 最快开始

**如果你正在和 Codex 对话：直接说“继续”“做秋季下一套”或“做这套：<文件夹>”。** 技能会读取唯一队列和当前断点，自动核对素材、模板与已完成页；你不需要先去面板复制提示词，也不需要反复讲已经写进 manifest 的内容。补封面时直接说“给这个成品补封面”。

一句话操作顺序：**选一套完整素材 → 选产线 → 选做法/模板 → 开始 → 等逐页质检和交付回执。** 在对话里，你可以直接说要做哪一套；在工作台里，只有明确标成“开始生成”的动作才会启动对应执行器。“登记请求”“素材已选中”“服务在线”都只是准备状态。

**如果你从团建容器的素材仓库开始：**

1. 在素材库的完整作品文件夹卡片点“选这套素材”；分类目录、散图不会作为一套发送。
2. 容器打开“内容制作”，展示所选文件夹和目标产线。CDP 只有在目标实例回传匹配的产线与实例身份后才显示“已带入”；若中途切换实例，旧实例收到的素材不会冒充新实例已收到。
3. 检查在线/本地模式、做法和模板后再操作。在线模式按钮走 GPT 网页/CDP 流程；本地模式的“登记请求”只保存请求，不会代发附件或启动生图。
4. 本地模式若要真实生产，仍需将素材交给当前 Codex 客户端对话；面板显示“容器已选中”或“请求已登记”都不代表模型已收到素材或开始生成。
5. 只有图片、对应文案、来源映射、manifest 和要求的入库回读都齐并通过，才算完成。

固定模板新对话是可选方式：只有你想把对话专门留作一个母版时才初始化。日常继续生产可以留在当前对话；Codex 每次真实生图仍须把当页源图与 P1/P2 实物交给工具。

**重要：** 容器选料回执、工作台请求登记和技能本身是三种不同状态。它们都不能替代真实模型调用、图片落盘、独立质检或云端回读。

## 怎么判断真的完成

- 图片数量和每张有效源图一一对应；
- 封面、内页、文字和事实检查通过；
- 本项目要求的 11 版本文案齐全；
- 本地成品、来源映射和 manifest 对得上；
- 要进飞书时，新增记录、图片和版本信息能重新读回来。

少一项就显示未完成并写明缺什么。网页看起来成功、状态写着 PASS、任务已登记，都不能单独代替本地文件和质检证据。

## 在线模式：用一句话创建计划（2.6.32-dev，本地代码，运行验收待完成）

1. 在素材区输入关键词即时筛选，或直接写完整需求；有需要就勾选整套素材。
2. 选择制作方式、模板；固定模式可在计划中保存多个模板候选，每套开工前记录实际选中模板。
3. 点击“创建制作计划”。没有素材也能保存，状态是“等待找到素材”；不会偷偷选其他题材，也不会立刻生图。
4. 点击“查看计划进度”，展开计划，点“复制计划给 AI”，粘贴到操作对话。AI 读取同一后端计划，每素材一子任务；A/B 属于同一在线模式，可关联到同一父计划。
5. 图已生成仍显示待质检，只有文案、QA、归档和交付证据齐全才能算完成。目前尚未接通完整交付状态汇总，界面不显示虚假的完成数量。

计划不是硬链接副本，也不是另一本手工表格：现有 production-jobs/plans 保存原始需求与来源路径，子项引用 production-requests 的真实编号。前端和技能读同一份数据。文件夹名会因 Windows 字符限制安全处理，但原素材路径和原文件夹名独立保留；原标题必须从原素材核实，未知时不能猜。

谷歌云盘搜索/上传、谷歌日历完成通知尚未连接；当前没有云端端到端通过证据，不声称已可用。不要删除原素材或把内部 plan.json 当成云端成品。自动创建 Codex 对话、后台自动执行新计划、完整交付回写仍是后续待补工序。

## 进度里三种状态怎么理解

- “已生成 · 待质检”：有图片，还没有核实整套是否合格。
- “整套已核验 · 待交付”：所有图片与11版文案已核实，归档和云端还未确认。
- “验收后文件有变 · 待复核”：已核实的文件后来被改动，之前的合格状态失效。

以上都不会算成已交付作品。当前开发版的完整套图验收已接入本地任务；正式归档/云端完成回写和现场验收仍待完成。
