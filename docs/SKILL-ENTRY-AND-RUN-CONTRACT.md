# Skill 入口与客资统计运行契约

## 目标

工作台的 Skill 入口是业务技能的操作面，不重新实现业务规则。它把三层资产接在一起：

1. 技能本体：`wechat-teambuilding-conversion/SKILL.md`，回答怎么读取、判断、去重和写回。
2. 专属配置：`D:\AICode\AI\private-config\agents\jianghu-teambuilding-lead\`，回答为谁、从哪里读、写到哪张表、从哪一条水位续接。
3. 密钥与运行态：只从当前进程/本机凭据授权读取，回答凭什么执行；不进入源码、Skill、日志或页面。

## 页面行为

- Skill 卡片必须展示背景、步骤、WeFlow/飞书状态和当前门禁。
- “一键运行”默认启动只读预检和预览，不直接写表。
- 预览成功后显示“确认预览并更新表”，确认才进入 commit。
- commit 必须追加通过资格和查重的新客资，回读日期、联系方式、人数、地点、要求和资格判定；回读失败不得推进水位。
- 没有授权、运行态需要恢复、技能包不完整或没有执行器时，界面显示阻断原因，不猜联系人、不虚构写入结果。

## 后端接口

```text
GET  /api/skills
GET  /api/skills/wechat-teambuilding-conversion/status
GET  /api/skills/wechat-teambuilding-conversion/tasks
POST /api/skills/wechat-teambuilding-conversion/run
```

POST 默认 `mode=preview`。外部写入必须显式发送：

```json
{"mode":"commit","confirm":true}
```

## 执行器适配

工作台不会把 WeFlow 查询和飞书 CLI 逻辑复制成第二套。设置环境变量 `TB_LEAD_SYNC_RUNNER` 指向已授权的本地执行器后，工作台按以下约定调用：

```text
<runner> --mode preview --output json
<runner> --mode commit  --output json
```

执行器继承当前进程的授权环境，但必须自己遵守技能本体的增量水位、本人身份过滤、10 人及以上门槛、查重、中文逗号备注、预览后写入和写后回读规则。标准输出最后一行返回 JSON；工作台只保留统计字段，不保存原始聊天内容、token 或 Cookie。

## 验收

至少覆盖：

- 10 人及以上客资通过，低于 10 人/个人需求排除；
- 同事截图不进入本人表；
- 联系方式按电话、微信号、原始微信 ID、昵称复核降级；
- 转发记录和截图可合并，跨群同图只计一次；
- 重复运行幂等；
- 缺少授权或状态需恢复时硬停；
- commit 后每条回读通过才推进水位。

## 团建主链技能中心

技能中心不是插件市场，也不复制技能源码。它从本地共享技能真源读取说明书和注册元数据，展示：

- 分类、来源路径、当前状态和是否有安全执行器；
- 背景、用途、输入、输出、调用方式、运行方式和安全边界；
- 与素材扫描、内容制作、作品仓库、文件传输、在线分发、备份恢复之间的联动关系。

当前先接入项目主链的说明入口：

```text
素材扫描与标签 → GPT 内容制作 → 作品仓库 → 文件传输 → 在线分发
                         ↘ 系统自检 / 备份与恢复 / 项目状态交接
```

只有已经绑定安全适配器的技能才允许运行；仅有 `SKILL.md` 的技能显示“说明已接入”，不提供伪运行按钮。发送、移动、删除、发布、写入外部系统等动作必须继续沿用预检、确认、回读和可恢复规则。
