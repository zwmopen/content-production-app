# 设计说明

## 2026-08-23 图文生产阶段证据与恢复链（0.19.117）

- 自动生产只沿固定闭环前进：上传素材与计划 → 计划确认 → 完整生图 → 文案 → 下载打包归档 → 下一套素材。识别到更靠后的证据时不得回退到补图或新计划。
- 作品关注线与阶段截止分离：20 分钟无真实进展触发恢复升级；上传、计划、生图、文案、下载、归档分别使用有限分钟边界，超时保存检查点并进入原对话恢复链。
- 恢复顺序是原对话有限刷新、同账号浏览器重建、全自动窗口全部不可用时有序重启；刷新/重建/重启不计入图片额度，且不越过人工暂停、登录验证或真实额度。
- 四个账号窗口独立并行；应用启动或全局重启只对首轮窗口按既有 5–10 分钟错峰，窗口故障只修复自身。默认生产时间为北京时间 08:00–02:00。

## 2026-08-21 原 HTML 证据拆解与经营产出核算（0.19.64）

- 原 HTML 不再只作为一个独立文件入口或摘要卡片；工作台 `HTML复盘` 按业务职责拆成执行摘要、漏斗、成交案例、成交产出、避坑、SOP、百问百答、AI、团队、上帝视角和维护方法。
- 每个模块保留“复盘卡片”与“原 HTML 证据表”两层：首屏看结论，展开查看原始表格，避免大表格挤满工作区；正式执行仍回到搜索、SOP、方案和决策树。
- 历史 HTML 快照、确认成交核算与当前 WeFlow 同步状态分层展示。API 恢复时只显示候选层变化，`formalWrite=false` 继续阻止候选内容污染正式资产。

## 2026-08-21 流量转化经营产出核算（0.19.62）

- HTML复盘继续作为原始 HTML 的复盘入口，新增“成交产出”模块，不把它改造成另一套知识库或正式 SOP。
- 经营产出只纳入有合同、发票、定金或执行记录等硬证据的 11 单，按实际执行月份归属；6–9 月金额、单数和总额在同一模块中可直接核对。
- 毛利按用户给定的 10%–25% 区间估算，界面同时提示直接成本范围和必须补齐的供应商、车餐住玩、税费、退款数据；不得把估算称为实际净利润。
- HTML 历史快照日期、成交产出核算日期和 WeFlow 实时同步状态分开显示；实时 API 不可用时仅标记待补，不用报价、计划或 `won_signal` 代替成交。
- 经营产出同时保留独立 HTML 文件 `docs/流量转化成交产出复盘.html`，页面入口与文件内容共用同一套已确认口径，便于脱离工作台查看或归档。
- 成交产出页补充持续更新与行业校准：维护技能按月对照聊天增量、成交/流失、报价、交付和毛利变化；候选与正式层分离，连续证据和人工确认后才调整 SOP、话术、决策树和 HTML。

## 2026-08-18 GPT 全自动持续恢复边界（0.19.31）

- 单账号全自动的核心不变量是：工作时段内普通网页、网络、检查点、归档和解析故障不把窗口留给人工点击；先从当前检查点退避重试，连续失败的当前作品顺延或隔离，剩余队列继续。
- “额度等待”是唯一的自动等待原因之一：额度/低产出信号只影响当前账号，下一次探测时间写入持久状态，到时间自动续跑；不把额度等待冒充普通失败。
- `07:00–02:00` 只限制自动生产时段。时段外保持队列和检查点，不运行上传或生图，到下一次开始时间自动唤醒；暂停、停止、手动模式和登录/验证仍保留为明确外部边界。
- 普通恢复动作不重新选择已完成素材、不增加使用次数、不移动源目录；只有服务端确认下载、打包和归档完成后才进入完成账本。

## 2026-08-18 HTML复盘与维护技能入口

- 流量转化最右侧使用“HTML复盘”作为用户语言，不再把它做成新的“全链路知识库”。原始报告按执行摘要、漏斗、成交、避坑、SOP、百问百答、AI、团队、上帝视角和维护方法拆成模块。
- 模块标注“工作台执行 / 复盘参考 / 只给维护技能”，避免把历史分析直接冒充当前正式话术；执行入口回到搜问题、转化 SOP、方案和决策树。
- “流量转化模块维护”是唯一维护入口：建立基线 → 检查服务 → 核对正式层 → 对照成交与行业变化 → 筛选 HTML 模块 → 输出缺口 → 人工确认后写回。默认只读，不自动覆盖正式资产。
- 技能中心卡片采用渐进披露：模板仓库技能把背景、用途、对象和输入方式合并为三秒悬浮“介绍”，安全边界单列；启动后才显示带箭头的运行步骤，未运行时不增加卡片高度。

## 2026-08-17 朋友圈月采集失败后补采（0.19.24）

- 默认每月 1 号采集；若当天服务未运行或 API/目标暂时不可用，接下来默认 6 天继续补采，直到成功或窗口结束。
- 每天最多尝试一次，避免失败时连续请求；只有 `COMPLETED` 才锁定当月，失败会保留原因和 traceback/日志线索。
- 设置中心公开“错过后补采天数”，用户可以把窗口缩短为只认 1 号，也可以保留默认 7 天；素材始终写入已有作品库。
- 月度采集时间保持独立；每日准备当前改为北京时间 `10:00–12:00` 窗口，窗口内工作台恢复后尽早执行，超过窗口不补发。每日准备只停在微信发表前，最终发表仍由人工确认。

## 2026-08-17 朋友圈自动选材与发送前自检（0.19.22）

- 自动选材使用明确级联：去年今天 → 去年本月稳定随机 → 历史同月稳定随机；没有符合条件的作品就停止，不随机跳到无关月份。
- 朋友圈页把“定时模式 / 自动额度 / 下次触发 / 最近结果”放在页头，用户不需要进入设置才能判断自动任务是否仍在工作。
- “发送前自检”是只读门禁，检查当前作品状态、原始文案和媒体，不打开微信、不写发布状态；通过后才进入原有“发送到微信待发布”人工最终确认链。

## 2026-08-16 全应用模块说明标准（0.19.05）

- 每个主要模块、技能卡、页面帮助入口和动态工作区都必须提供说明契约：背景、用途、对象、怎么用、如何运行、为什么/边界。
- 桌面鼠标悬停超过 3 秒、键盘聚焦超过 3 秒使用同一说明层；指针离开、失焦、页面切换或模块销毁时立即取消。触摸设备直接展示关键说明，不把信息藏在不可用的 hover 里。
- 新模块优先使用 `data-help-module="true"` 与 `data-help-id` 注册专属说明；没有专属注册时由统一模块选择器提供安全兜底，但不能把内部状态名当成人话说明。
- 技能卡保持紧凑，卡片上必须有“悬停查看说明”可见提示；高风险按钮仍需自己的动作说明和确认边界，模块说明不能替代执行前确认。
- 动态列表必须使用事件委托，说明层不能阻挡原有点击、输入、拖拽和键盘操作；说明文案必须与后端真实输入、流程、结果和安全边界同步。

## 2026-08-15 技能中心通用交互规则（0.18.85）

- 每个技能卡、小工具和链路节点都要有可读说明，不依赖用户猜测内部名称；桌面鼠标悬停三秒、键盘聚焦和触摸设备均使用同一套六段说明。
- 右键是技能模块的上下文设置入口，统一提供“打开技能设置、设置输入/输出路径（若支持）、查看技能说明、复制技能 ID”。右键不直接执行移动、删除、发布等高风险动作。
- 设置必须属于技能自己的配置边界。素材处理的输入下载区和输出素材库路径可以选择、打开和保存；其他技能如果尚未提供可编辑配置，显示清楚的只读状态，不做假设置。
- 路径保存前必须验证真实文件夹、必要目录结构和输入输出不互相嵌套；保存后重新读取技能状态，用户仍需走预览确认门禁。

## 2026-08-15 素材处理技能中心入口（0.18.84）

- 一级导航明确显示“技能中心”；技能中心是本地技能入口，不把每个技能误做成常驻 AI 员工。
- “素材处理”卡片显示扫描、完整帖识别、20 字命名/指标、标签、预览和整包入库五段流程；先预览再确认是主操作顺序。
- 设置中心为每个技能预留独立开关，本轮先落地 `启用素材处理`；关闭入口不改变文件和配置真源。
- 结果卡片优先展示用户能核对的数量：完整帖子、预计/已移动、空目录和残留待确认；路径与下一步作为补充，不把原始脚本日志堆到界面。

## 2026-08-15 江湖工具箱素材入库边界（0.18.69）

- 江湖工具箱负责下载，`jianghu-toolbox-material-ingestion` 负责下载后整理，图文工作台素材区负责浏览、筛选和选用；三者是连续链路，不各自维护一份素材状态。
- 入库技能只接收图片加 TXT/MD 的完整帖子，文件夹名最多20个可见字符，评论在点赞前；标签必须同时进入目录 `.tags.json`、集中台账和全局索引。
- 素材区帮助必须解释来源、刷新方式和残留边界；视频、散落 TXT、非完整帖子与超相似候选不自动删除。

## 2026-08-15 小红书话术版本与转化回复操作（0.18.65）

- “树状图”必须配一段人话解释：它是按客户信号逐格判断的路径，不是组织架构图，也不是要求新人一次读完整棵树。
- 小红书固定评论话术允许多个版本共存，但每个版本必须有适用备注；企业号明确版和克制版都可复制，带备注的多版本默认展开。
- 转化 SOP 的主操作是复制，不是点赞；回答操作区右对齐，减少无关动作干扰新人执行。

## 2026-08-15 决策树执行进度（0.18.64）

- 用户旅程地图首屏必须明确唯一当前动作：进度卡显示当前节点、完成数量和下一步提示，避免新人在 8 张卡片之间猜“现在该做什么”。
- 节点动作不是装饰：完成并进入下一步写入当前浏览器的 localStorage，并优先沿当前节点的 yes.target 自动定位；从这里开始/重做这一步会切换当前节点并清理其后的完成标记。
- 进度属于操作员的本机执行状态，不进入正式 SOP、候选聊天、原始素材或外部旅程画板；树新增节点仍以唯一 id 和 branches.*.target 为兼容边界。

## 2026-08-14 发送按钮背后的微信前置技能（0.18.63）

- “发送到微信待发布”仍保持单一主动作，但动作背后先执行可解释的前置链：检查进程 → 启动微信 → 检查窗口 → 登录窗口只点击一次“进入微信” → 等待人工登录 → 打开朋友圈 → 加图 → 填文案 → 停在发表前。
- 登录和验证码属于用户身份边界，面板只提示并等待，不代填、不绕过；等待超时允许用户完成登录后继续同一条素材。
- 运行中的状态提示必须区分“等待人工登录”和“技术失败”，避免把用户还没扫码误显示成素材损坏。

## 2026-08-14 朋友圈素材到待发布面板（0.18.62）

- 首屏先给“今天发哪一条”的筛选和封面列表，再在右侧展示九宫格与原始文案，减少在文件夹和微信窗口之间来回核对。
- 默认策略是“今年素材”；“去年的今天”和“全部历史”必须由用户明确切换。分类、标签来自作品的 `asset.json`，不在界面里臆造 AI 标签。
- 发送按钮的文案明确写出“只准备，不自动发表”，并在执行前再次确认；失败只显示阶段和日志线索，不自动换下一条、不连续重试。
- 所有高风险控件保留 `title`/说明入口；打开素材目录是只读辅助动作，不移动、不删除、不改写源文件。

## 2026-08-14 流量转化内容可用性边界（0.18.46）

- 流量转化是同一个工作台里的一级业务页，不显示“等待连接/模块不可用/重新加载”作为正常入口状态。
- 固化的 SOP、基础判断规则和可复制话术随工作台内置，进入页面即可使用；完整历史问答与方案索引允许后台同步后再补齐。
- PDF、PPT 等体积较大的外部资料仍按配置路径读取，路径不可用时只提示外部资料暂不可用，不影响内置文字能力。
- 这条边界是渐进增强：内置内容负责可靠可用，外部服务负责扩充，不建立第二套平行知识库。

## 2026-08-14 在线分发平台状态边界

- 在线分发采用紧凑页头 + 平台 tab + 平台工作区；已接入平台复用真实业务链路，待接入平台只呈现状态和边界说明。
- 平台 tab 的选中状态必须同时由视觉样式和 `aria-selected` 表达，避免用户把占位平台误认为可发布入口。
- 携程、小红书、抖音未完成真实接入前不得出现假登录、假上传或假发布；公众号仍保留作品集、草稿检查台、原生编辑器和状态恢复。

## 2026-08-14 分发记录的人话解释层

- 分发原始日志继续承担审计和机器恢复职责；工作台默认显示“结论 → 关键对象 → 时间”，把路径、文件数、大小、库存阈值、重试和技术追踪号放进可展开详情。
- 设备接收、公众号操作、文件夹移动和自动库存判断统一经过同一套前端解释层，不能只把 JSON 事件名或内部状态直接展示给用户。
- 自动分发完成后，工作台只读刷新 dashboard 的分发快照并重绘历史，不重新创建传输任务；文件夹和防重复账本仍是事实真源。

## 2026-08-14 跨端兼容与通用分发基线

- 图文项目工作台由一个电脑端控制台和配套手机接收端组成；手机端不是某个品牌的临时插件，而是统一设备协议的适配实现。
- 必须长期保留小米、红米、VIVO、华为 Android 设备，并为 Apple iPhone 预留同一协议的 iOS 接收端适配。没有实机证据的设备只能标记“待验证”，不能宣称已兼容。
- 设备发现、分类库存、传输、校验、成功去重、失败重试、断线恢复属于通用内核；精准/泛流量、内容类型、目录、平台名称和阈值属于可配置 profile。
- 所有新功能遵循“先手动可验证，再自动运行”：先完成一次真实手动发送闭环，才允许自动补货；库存未知、未授权、无候选或重复作品时必须安全跳过并显示原因。
- 手机端升级必须经过跨设备回归，不得只修当前手机而破坏其他品牌；保留旧包、签名链、数据目录和恢复路径，禁止升级清空作品或登录数据。

## 0.17.0 信息架构

- 六个一级入口：内容制作、作品库、设备分发、在线平台分发、流量转化、设置中心。
- 作品库面向正式资产；设备分发面向任意电脑文件与设备传输，两者不互相替代。
- 在线平台分发使用统一平台 Tab；未接入平台必须明确写“待接入”，不可模拟成功。
- 设置中心通过七类入口渐进展开，成熟控件和真实保存逻辑不能因为 IA 迁移被删除。

## 0.16.15 一级导航减法

- 用户的真实闭环是“生产作品 → 归档作品 → 分发作品 → 承接流量”，一级入口只保留内容生产、内容分发、流量转化和设置中心。
- 插件市场只做外部工具目录，不拥有任务状态，也不参与任何作品闭环，因此从界面、助手意图和帮助系统同时退役。
- GPT 浏览器扩展属于内容生产的执行内核，不是用户需要挑选的商品；继续内置运行，但不再重复展示版本卡和本地路径。
- 旧的活动页本地记忆指向 `plugins` 时安全迁移到内容生产，避免升级后出现空白页。

## 0.16.0 标准层与开发层共用一套产品

- 不创建“定制版”和“商业版”两套长期分叉应用；同一套源码、运行数据和配置真源提供两层界面。
- 标准层默认面向普通用户，只要求完成“生产方式 → 工作流确认 → 账号窗口”三步，并直接给出当前模式、账号、额度和运行状态。
- 开发层收纳完整工作流编排、逐步提示词、超时、重试、并行参数、API 与诊断；默认折叠，但所有能力仍真实可编辑和保存。
- 首页快捷入口必须指向原有真实控件，禁止复制一份只展示不生效的配置；运行中修改继续遵循“当前作品冻结、下一套生效”。
- 商业通用版后续通过默认配置、首次使用向导、品牌与功能开关形成发布入口，而不是复制仓库后各自修 Bug。

## 0.12.2 内容生产（自动）

## 目标

把团建内容生产、作品集库存、设备分发和公众号补笔记集中在一个本地工作台，降低寻找目录、判断资格和重复点击的成本。

## 分层

工作台只是一层界面和状态机。项目推进目录是业务事实真源；共享 Skill 是工作流规则真源；运行数据目录承载可重建状态和日志。三者不互相复制。

## 界面

- 设置集中在一个页面：上方是拟态/玻璃两种显示模式，中部是目录、坚果云和自动化规则，下方是数据、扩展、版本和高级入口。
- 素材区遵循“先看分类、再读内容”：首次打开只读取当前分类，切换或展开时再加载目标分类，并保留文件夹原结构。
- 左侧工作流固定为素材生产、作品集、分发功能和设置；素材生产是默认入口。
- “生产数字作品”由独立浏览器扩展服务；工作台提供本机目录、文件流、历史状态和回退入口。
- 浏览器调试版不绘制假的聊天记录，也不伪装成已经接入的 ChatGPT。
- 作品集负责库存、平台资格和历史；分发功能负责执行与记录。
- 手动按钮和 Codex 指令必须调用同一套规则。
- 视觉默认采用冷灰蓝拟态，并可切换半透明玻璃主题；控件保持紧凑、低对比和清楚的选中态。
- 确认、输入、错误和完成反馈统一使用软件内部弹层，不调用浏览器原生对话框，不向用户暴露执行内核术语。

## 原则

1. 不移动或改写业务素材结构。
2. 所有根路径允许通过环境变量覆盖。
3. 可变状态不写入源码仓库。
4. 打开本地路径前执行允许根目录校验。
5. 分发不复制共享 Skill 的传输和 Junction 清理逻辑。
6. 公众号“已打开过”不等于上传完成，必须人工确认。
7. 所有需要人工寻找和切换的外部操作统一归口到工作台，但不复制出第二份可独立修改的源码。
8. 已经跑通的油猴、VBS、PowerShell、本地协议和共享 Skill 优先作为执行内核直接复用；工作台负责入口、参数、任务绑定、进度和结果。
9. 外部能力按“直接调用 → 适配器联动 → 稳定后内建模块”渐进升级，每一步都保留旧入口和恢复路径。
10. 网页能力必须使用真实网页和真实登录会话；浏览器扩展、桌面工作台和共享 Skill 分别维护独立产品边界。
11. 任何真实分发必须先建立可见任务；任务至少显示目标、当前阶段、百分比、停止入口和最终结果，页面刷新后仍可恢复。

- `TEAMBUILDING_ROOT`：业务项目根目录。
- `TEAMBUILDING_SKILL_ROOT`：团建提示词资料根目录。
- `TEAMBUILDING_DASHBOARD_RUNTIME`：控制台状态和日志目录。
- `TEAMBUILDING_PUBLISH_ROOT`：发布空间目录。

# 0.9.6 生产入口设计

素材生产页的首要动作是“得到什么”，不是“调用什么接口”：

- 做一张：用户选择封面或内页，适合补页、单张发布或快速验证。
- 做一套：系统按有效素材拆分页面，输出独立轮播图片、文案和记录。
- 批量做：从当前素材开始连续处理多套，统一使用当前模板配方。

第一次点击生成计划，第二次确认启动生产。接口参数默认收起；A/B/C、事实锁、价格触发、3:4 独立页、历史结果隔离等规则由系统内部承担。
# 0.19.23 朋友圈每月采集

设置中心提供“每月自动采集一次”开关、日期和时间。默认关闭；启用后只允许每月 1–28 日，使用当前账号/UID、采集数量和素材库目录。成功、失败或缺少目标都消耗当月运行键，避免后台连续重试；采集结果继续进入现有 `D:\朋友圈weflow`，不影响人工确认的每日发布流程。
