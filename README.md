## 🎯 痛点与初衷：为什么需要它？

在多账号、矩阵化自媒体内容工业化生产实践中，传统网页端操作和单脚本批量处理面临四大致命瓶颈：
1. **多账号串号与环境污染**：传统浏览器多开或多标签页共享相同或交叉的存储上下文，极易发生 Cookie 串扰、账号混淆，甚至触发平台的安全风控；
2. **长对话大 DOM 树导致连接闪退**：CDP 控制协议在读取数十轮上下文的长对话大页面时，默认缓冲区过小，极易抛出 `sent 1009 (message too big)` 异常导致生产进程骤然崩溃；
3. **断流假死与无头死等**：大模型在生成超长文案或批量图片时，若前端扩展偶发断流、停留在“等待输入 1 确认”时，常规脚本只能无限挂起，导致整个通宵的无人值守流水线全面瘫痪；
4. **下载损坏与图文脱节**：传统整包 ZIP 下载极易因网络波动损坏，且经常出现“只有图片没有文案”或“文案齐全却缺图”的次品事故。

**AI 图文批量生产控制台正是为彻底打通大规模生产断层而研发——以“四核物理进程隔离”、“底层 CDP 按键穿透自愈”、“20MB 防溢出管道”与“严密质量门禁”，实现 24 小时连续高产的工业级闭环。**

## ❓ 常见问题解答

### Q1: 为什么要采用多进程独立实例，而不是单窗口内开 4 个标签页？
在 Chromium 架构中，单进程内的多个标签页共享同一渲染管线与事件循环，一旦某个标签页因长会话造成内存泄漏或崩溃，会导致所有正在生产的标签页全军覆没。此外，不同账号登录态必须完全隔离，四进程独立模型在系统资源充足的情况下具备最顶级的健壮性。

### Q2: 生产过程中遇到网络抖动怎么办？
系统具备多层重试与自愈机制：首先通过本地代理隧道保持连接稳定；其次针对通信管道设定了心跳检测与重连逻辑；若出现断流，系统会触发物理级按键点火推进会话，无需人工在深夜值守排查。

### Q3: 生产完成的作品存放在哪里？
每套作品经质量门禁校验合格后，会自动保存至对应合集目录中，包含完整的 4K 原图文件与配对的文案文件，并由去重账本登记，防止后续环节混淆。

### Q4: 详细的版本历史与技术演进细节在哪里？
完整的版本变更纪要与生产优化历程请查阅 [`CHANGELOG.md`](CHANGELOG.md)。

## 本地开发 2.6.23-dev：CDP 固定模板消费与回执边界

CDP 桌面桥只接受明确的固定模板模式，并会在 GPT 扩展实际附件列表中核对 P1/P2 文件字节、SHA-256 和输入框预览后，回写原始请求的 `MATCH` 回执。`MATCH` 只证明模板附件已被本次浏览器输入接收；当前固定模板自动生产 worker 尚未接通时，界面明确返回“未开始生产”，暂停该窗口以免下一套混入，不会把上传显示为作品成功。模式 1/2 暂不支持，会明确拒绝。

Codex API 请求准备会先拉取新鲜的统一状态快照，并在提交和回读中绑定同一条产线、模式、模板与配置版本。定向回归 15/15；未启动浏览器、模型或飞书，桌面实机验收仍待安全窗口进行。

## 在线模式：用一句话创建计划（2.6.32-dev，本地代码，运行验收待完成）

1. 在素材区输入关键词即时筛选，或直接写完整需求；有需要就勾选整套素材。
2. 选择制作方式、模板；固定模式可在计划中保存多个模板候选，每套开工前记录实际选中模板。
3. 点击“创建制作计划”。没有素材也能保存，状态是“等待找到素材”；不会偷偷选其他题材，也不会立刻生图。
4. 点击“查看计划进度”，展开计划，点“复制计划给 AI”，粘贴到操作对话。AI 读取同一后端计划，每素材一子任务；A/B 属于同一在线模式，可关联到同一父计划。
5. 图已生成仍显示待质检，只有文案、QA、归档和交付证据齐全才能算完成。目前尚未接通完整交付状态汇总，界面不显示虚假的完成数量。

计划不是硬链接副本，也不是另一本手工表格：现有 production-jobs/plans 保存原始需求与来源路径，子项引用 production-requests 的真实编号。前端和技能读同一份数据。文件夹名会因 Windows 字符限制安全处理，但原素材路径和原文件夹名独立保留；原标题必须从原素材核实，未知时不能猜。
